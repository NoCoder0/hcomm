# 六段骨架写作规范

> 通用 Markdown 写作基线：目标仓存在 `.agents/skills/hcomm-review/references/markdown-writing.md`（hcomm 仓）时，直接加载该文档作为写作规范基线（文件命名/标题/列表/表格/标点/链接/注释符号/敏感词等 14 类规则），本文不复制其内容、与其冲突时以仓内规范为准。仓内规范缺失时，按本文末尾"最小写作基线"执行。

## 1. 功能描述（Feature Description）

结构：定位一句话 → 分侧职责 → 使用场景 → 与周边模块的关系 → 核心能力编号列表。

- **定位一句话**：说明模块属于什么体系（如 HCCL DFX 子系统）、负责什么、在哪个路径。例：
  > taskException 模块是 HCCL 集合通信库中的 **DFX（Design for eXcellence）异常诊断子系统**，负责在集合通信任务执行失败时进行异常捕获、错误信息解析、诊断日志打印和错误上报。

- **分侧职责**：模块横跨 Host/Device 两侧时，用列表分别写清每侧职责（Device 侧按实际执行单元写实名，如 AICPU、CCU、MC2）。单侧模块可省。
- **使用场景**：写清"谁、在什么流程中、什么条件下会用到该模块"——上游调用入口、典型业务流程（如"集合通信任务下发失败时"）、典型用户/使用者（如框架层、上层组件）。例：
  > 在集合通信任务执行失败（hccl 返回错误）时，由框架的异常处理路径调用本模块解析并上报错误详情。
- **与周边模块的关系**：概览级写清三向关系——**依赖**（调用哪些周边模块的什么能力，如"依赖 RTS 提供回调注册机制"）、**被依赖/被调用**（哪些周边模块/框架在什么流程中调用本模块）、**交互机制**（通过什么接口/回调/队列交互）。此段是模块粒度的概览，文件级与函数级的展开归目录描述（文件间关系表）与流程描述（时序图）章节，不在此重复。例：
  > 依赖：RTS（回调注册/异常通知）、HCCP 算法库（错误码解析）；被调用：HCCL 任务执行路径在任务失败时进入本模块。
- **核心能力**：3~9 条，动词开头，每条对应到具体接口或流程。例："向 Runtime 注册/注销异常回调函数"。
- **功能描述章节重点写功能本身，不展开接口细节**。若模块有对外 C 接口（hccl_diag.h 等），可在功能描述末尾加"对外接口"小节，但只做**功能级简介**：每条对外功能一句话说明、搭配接口名即可（如"注册算子信息到通信域（`HcclDfxRegOpInfoByCommId`）"），不列参数表；**详细的接口描述（全量参数表）统一放接口描述章节**，两处不重复。

## 2. 目录描述（Directory Description）

三件套，顺序固定：

1. **目录树**：`text` 代码块，每个文件一行注释。多级子目录缩进对齐。跨目录引用的文件单独再放一棵树并注明路径（如 ccu_dfx/ 位于 base_comm/resources/ccu/）。废弃文件标 `[已废弃]`。
2. **文件间关系表**：三列（文件/功能/依赖关系）。依赖关系写具体：依赖哪个头文件的什么东西（"依赖 `ccu_kernel_mgr.h` 获取 CcuRepContext"），不写空话。
3. **组件交互图**：Mermaid `graph TB`，subgraph 分组（外部调用者/Host侧/Device侧/外部组件），边上标函数名。跨侧交互用不同 subgraph 表达。

**目录特征**（可选）：小模块可加一段文字说明目录在仓库中的位置、实例由谁持有、不依赖目录内哪些文件。

## 3. 流程描述（Flow Description）

- **覆盖全部核心流程**，按"注册/初始化 → 主处理（按模式分） → 异常/退出路径"的叙事顺序排列，不挑不漏。模块有 N 个运行模式（Aicpu/CCU/MC2…），每个模式的 Host 侧/Device 侧主流程都各自成图。**与周边模块/组件的交互流程（回调注册、事件通知、数据上报等）也属核心流程，必须成图**。
- 每流程一张 Mermaid sequenceDiagram，标题格式：`#### <流程名>（<入口函数>）`。
- 图内要素：
  - participant 优先直接用类名（保持可直接检索）；确需简化时，**每张时序图内**使用该别名的 participant 须在本图首次出现处用 `participant 别名 as 类名` 完整声明（如 `participant HCD as HcclCommDfx`）——Mermaid 每个代码块独立渲染，别名声明不跨图生效，复用别名的新图需重新声明；
  - **外部模块/组件的类、回调、接口作为 participant 画进图**——跨模块消息（进出本模块的调用、回调触发）是流程完整性的一部分，涉及哪个画哪个，不回避；
  - alt/else 表分支，loop 表循环，Note 标注关键行为（如"首个 comm 注册时调用 aclrtExceptionInfoCallbackRegister"）；
  - 关键常量值直接写进 Note（如"最多 50 条"）。
- 错误码转换表紧跟所属流程之后，列：源字段/目标字段/常量名/值/说明，表前注明源码行号。例：
  > **SendTaskExceptionByMBox 错误码转换表**（源码：`hcclCommTaskExceptionLite.cc:429-435`，常量定义：`hcomm_task_scheduler_error.h`）

## 4. 数据描述（Data Description）

**章节定位**：以类图（Mermaid classDiagram）描述核心类的**结构与关系**。**类图为主，不严格类图 only**——类图装不下的重要数据形态（裸结构体数组、宏定义常量表等）允许章内用表格等更合适的载体呈现，但"核心类必须进类图"底线不变。**与接口描述的分工**：类图呈现类的**结构形态**（成员变量/方法签名/关系线），行为语义（做什么/关键分支/触发条件）由接口描述章节承载，不在类图中展开。

- 存量文档此段标题可能为"接口描述（类图）"或"数据描述（Mermaid类图）"——均为历史变体：类图描述的是数据/类结构，接口描述是其后的独立章节（本骨架第 5 段）。**新写文档一律用裸标题"数据描述"（章节名不加括号后缀）；触碰更新存量文档时按"存量文档更新策略"建议调整（需用户确认）。**

- Mermaid classDiagram **覆盖全部核心类**（含关键数据结构类：错误信息结构、上下文结构等），过多时可按侧别拆多张。
- 每个类框写全：成员变量（`-` 私有 `+` 公有）、方法签名（参数类型+返回值）、`$` 后缀表静态方法。
- 泛型写法：`vector~CcuErrorInfo~`（用 `~` 转义尖括号）。
- 关系线：`..>` 依赖、`o--` 持有、`-->` 使用，**线上标短语既要写用途也要写交互机制**（函数调用 / 回调 / 通知 / 数据上报，如 `TASK_CCU时分派`、`异常回调`）。
- **外部组件（hccp、rts、hal 等非本目录类）必须画进图**，作为依赖终点；本模块对外提供的回调、被周边调用的入口同样以关系线表达（方向：外部类 → 本模块类），不只画单向依赖。

## 5. 接口描述（Interface Description）

**对外判定标准（按调用边界，非语言可见性）**：一个接口是否"对外"，以**模块目录之外是否存在调用**为准（含经回调注册被外部组件触发），与 public/private 无必然关系——核心类的 public 方法可能仅供模块内部使用，private 回调也可能被外部触发。探查阶段（Step 1）通过 grep 调用点判定。

**章节结构：对外接口总表（索引）在前 → 按类完整表（详写）在后。**

1. **对外接口总表（全量，索引性质）**：模块对周边组件/模块提供的**所有**功能接口逐个入表，一表列全：
   - extern "C" 入口函数（hccl_diag.h / hcomm_diag.h 等暴露的函数）；
   - 门面类/核心类中被模块外调用的公有方法；
   - 注册给外部组件的回调（`RegisterXxxCallBackHcomm` 类）；
   - 跨模块可见的全局函数。

   表列：接口 / 所属类或头文件 / 调用方 / 一句话功能。**总表只做索引**（一句话功能，不展开参数），详细描述一律在类表，两处不重复——总表行的"功能"列与类表"功能说明"列是简繁两级，非同一内容两写。
2. **按类完整表（详写，唯一详写落点）**：每个核心类一张五列表，类的**全部核心接口**都在（含对外方法——一个类横跨模块内外是常态，对外公有方法在"类型"列标注**"公有（对外）"**，其余照常标"公有/私有"）。模块内部接口按详略分级：主流程必经方法详写（"做什么 + 关键分支/委托 + 触发条件"），辅助方法（getter/setter、纯工具函数、简单转发）从略或一行合并，注明"从略"的判断依据（如"纯参数存取"）。
3. **多组件目录**：探查发现目录含多个相对独立组件时，暂停并向开发者确认拆分口径后再写。

- 每个核心类一张表，按类分 `###` 小节；按侧别分组（Host侧/Device侧）。
- 表头固定五列：接口 / 类型 / 参数 / 返回值 / 功能说明。
- 参数列格式：`[in] name`、`[out] name`，多参数逗号分隔。
- 功能说明写清"做什么 + 关键分支/委托 + 触发条件"，不写实现细节。例：
  > `Register(u64)` | 公有（对外） | [in] commHandle | HcclResult | 将 commHandle 写入 CommRegisterMap_；首个 comm 注册时调用 aclrtExceptionInfoCallbackRegister(ProcessCallback) 向 RTS 注册异常回调
- 全局回调注册接口单独一张两列表（接口/参数/功能说明）。
- 接口表准确性核对（函数名/参数/返回值/参数解释逐项与头文件一致）沿用仓内 `.agents/skills/hcomm-review/references/markdown-api-accuracy.md` 的 PH/PA 规则。

## 6. 使用限制（Usage Limitations）

三个子节，前两个必有：

1. **支持的场景**：表格。列随模块而定（芯片/模式/Host侧/Device侧/说明），✅/❌ 表达侧别支持。
2. **规格约束**：编号列表。每条 **加粗小标题 + 具体约束**，必须引用常量名与具体值。例：
   > 1. **设备数量限制**：最大支持 65 个设备（`MAX_MODULE_DEVICE_NUM_V2 = 65`）
3. **已知限制**（可选）：编号列表，写设计缺陷与维护性债务（废弃未删的文件、无校验的输入、线程安全差异）。诚实标注，不掩饰。

## 通用规范

- **信息可佐证（红线）**：所有事实性陈述必须有代码或其他可靠资料（头文件、仓内权威文档）佐证，不展示证据但来源必须真实；禁止写入猜测、推断或编造的内容，确认不了的不写。
- 缩写首次出现必须括号注释：中文版"英文全称，中文释义"，英文版"Full Term (ABBR)"。全文只注一次。
- 数字规格（最多 50 条、65 个设备、256MB）出现即写具体值。
- 代码标识符一律反引号包裹。
- **标题统一**：中文 H1（一级标题）统一用"`<模块名>` 模块代码解析"格式（不用"功能说明"等变体）；英文版章节标题按 terminology.md 标准译名（`Feature Description` / `Interface Description` / `Usage Limitations` 等，不用 `Overview` / `API` / `Constraints` 等变体）。存量文档触碰更新时按"存量文档更新策略"处理标题差异（需用户确认）。
- 章节间用 `---` 分隔（小模块可省）。
- 全文不写"我们""读者"，客观陈述。

## 存量文档更新策略

更新已有文档（含补英文版、修改既有章节）时，除遵循前述各段规范外：

- **默认最小 diff**：只更新本次触碰的章节，未触碰章节不主动改写。
- **骨架对齐建议提出**：若触碰过程中发现存量骨架与标准六段不一致（缺段、标题变体、非标准扩展章节如"调用周期/配置方法/监控日志格式/模块组成与职责分工"），**暂停并建议用户**："存量文档骨架与统一骨架存在差异，建议按统一骨架调整结构，是否调整？"**不承认扩展章节的合法性**——经用户确认后调整结构（扩展内容并入标准章节或删除）；未确认前只改内容不动结构。
- **不涉及章节的处理**：按统一骨架补齐时，模块确实不涉及的章节（如纯软件模块无侧别差异、无对外 C 接口），该段保留标题并写明"不涉及"及原因（例："本模块仅 Host 侧运行，无 Device 侧职责"），**不裁剪章节**。
- **标题变体**（"接口描述（类图）"→"数据描述"、"数据描述（Mermaid类图）"→"数据描述"等）随骨架调整一并处理，未经确认不单独改标题。

## 最小写作基线（仓内 markdown-writing.md 缺失时的兜底）

| 类别 | 规则 |
|------|------|
| 文件命名 | 英文字母命名，多词下划线/中划线连接，≤50 字符；中文 `模块名.md` / 英文 `模块名_en.md`（单一流派；存量 README.md 命名触碰更新时建议改名） |
| 标题 | `#` 逐级递增，首行顶层标题；末尾不加标点；同级同类型结构一致；不手工加序号 |
| 代码块 | 3 反引号 + 声明语言类型；行内代码 1 对反引号；上下空一行 |
| 列表 | 有序用"数字."，无序统一符号；标记后加空格；术语项不加标点，句子项加句号 |
| 表格 | 标准 Markdown 语法，不用 HTML 表格 |
| 标点 | 中文全角、数字半角；单位与数字间不加空格；感叹号仅用于安全警告 |
| 链接 | 目标有效；仓内相对路径，跨仓完整 URL |
| 缩写/术语 | 首次出现有全称说明（与"通用规范"缩写注释一致） |
| 硬件代号 | 正文不使用 CKE/Xn/GSA/MS，替换为 Event/Variable/Address/CcuBuffer（代码块内标识符除外）；映射表见 terminology.md |
