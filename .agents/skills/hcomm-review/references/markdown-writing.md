# 检视规范：Markdown 写作规范

PR diff 含任意 .md 文件变更时加载本文（原型/参数核对见 markdown-api-accuracy.md）。规则基线来自 CANN 开源资料写作规范（cann/docs 仓 md-review-skill），严重级别沿用基线。

## 文件命名

| 编号 | 规则 | 严重级别 |
|------|------|---------|
| FN-01 | 文件名以英文字母命名 | MEDIUM |
| FN-02 | 多个单词以下划线或中划线连接；同目录内命名风格保持一致（comm_mgr_c 用 PascalCase，comm_mgr_python/comm_opdev 用下划线） | MEDIUM |
| FN-03 | 文件名不宜超过 50 个字符 | LOW |
| FN-04 | 中文 README 命名为 README.md，英文命名为 README_en.md | HIGH |
| FN-05 | 同一目录下不能出现重名文件 | CRITICAL |
| FN-06 | 新增文档以 .md 结尾 | HIGH |

## 标题

| 编号 | 规则 | 严重级别 |
|------|------|---------|
| HD-01 | 标题简洁明了，概括章节核心内容 | LOW |
| HD-02 | 操作类标题使用动宾结构；同级别同类型标题结构保持一致 | MEDIUM |
| HD-03 | 标题末尾不加标点，避免特殊字符，补充说明使用圆括号 | MEDIUM |
| HD-04 | 标题与正文间空一行 | LOW |
| HD-05 | 标题使用 # 格式且级别逐级递增，第一个标题是顶层标题 | HIGH |
| HD-06 | 标题中不手工添加序号（## 1. 安装 应改为 ## 安装） | MEDIUM |
| HD-07 | 标题建议最多四级 | LOW |

## 字体样式

| 编号 | 规则 | 严重级别 |
|------|------|---------|
| FS-01 | 斜体使用一个星号 | LOW |
| FS-02 | 粗体使用两个星号 | LOW |
| FS-03 | 粗斜体使用三个星号 | LOW |
| FS-04 | 对特定内容使用转义符 | LOW |

## 图片

| 编号 | 规则 | 严重级别 |
|------|------|---------|
| IMG-01 | 图片以英文小写命名，多单词下划线连接，名称不超过 50 字符 | MEDIUM |
| IMG-02 | 图片统一存放到文档同级目录下的 figures 文件夹，使用相对路径引用 | HIGH |
| IMG-03 | 使用原创图片，避免侵权 | HIGH |
| IMG-04 | 图文配合使用，切忌图文分离 | MEDIUM |
| IMG-05 | 图片格式首选 PNG，次选 JPG | LOW |
| IMG-06 | 中文文档使用中文插图（中英文文档分别使用对应语言的插图） | MEDIUM |
| IMG-07 | 截图只保留核心内容，关键信息可用红框或文字标注 | LOW |
| IMG-08 | 图片清晰可辨 | LOW |

## 代码块

| 编号 | 规则 | 严重级别 |
|------|------|---------|
| CB-01 | 代码逻辑和语法正确 | HIGH |
| CB-02 | 清晰区分输入与输出部分 | MEDIUM |
| CB-03 | 关键步骤有注释说明 | MEDIUM |
| CB-04 | 行内代码和命令行使用 1 对反引号 | LOW |
| CB-05 | 块级代码使用 3 个反引号并声明语言类型，上下空一行 | MEDIUM |
| CB-06 | 语言类型正确声明（c、c++、bash、json、yaml 等） | LOW |

## 列表

| 编号 | 规则 | 严重级别 |
|------|------|---------|
| LS-01 | 有先后逻辑顺序用有序列表，并列/多选一用无序列表 | MEDIUM |
| LS-02 | 术语/短语列表项统一不加标点；完整句子统一加句号；混合情况统一加句号 | LOW |
| LS-03 | 无序列表标记后必须添加空格 | MEDIUM |
| LS-04 | 同一文件同一层级的无序列表使用同一符号 | LOW |
| LS-05 | 有序列表使用数字加点号，不支持字母序号 | MEDIUM |
| LS-06 | 嵌套列表在子列表项前添加两个或四个空格（不使用 tab） | MEDIUM |

## 注释符号

| 编号 | 规则 | 严重级别 |
|------|------|---------|
| NT-01 | 根据场景选择恰当的注释符号（NOTE/CAUTION/WARNING） | MEDIUM |
| NT-02 | 注释块内可嵌套列表，不建议嵌套表格和代码块 | LOW |
| NT-03 | 使用连续的 > 符号保证样式不中断 | MEDIUM |
| NT-04 | 说明/注意等内容简洁，过长迁移至正文 | LOW |

## 链接与锚点

| 编号 | 规则 | 严重级别 |
|------|------|---------|
| LK-01 | 链接目标有效，避免死链（仓内文件用相对路径，跨仓用完整 GitCode URL） | HIGH |
| LK-02 | 引用文档时用书名号包裹并添加超链接 | LOW |
| AN-01 | 引用文档内标题、图片或表格时使用锚点 | MEDIUM |
| AN-02 | 锚点生成：大写字母转小写、空格替换为中划线、去除特殊符号 | LOW |
| AN-03 | 锚点方法二：使用 `<a>` 标签自定义锚点 ID | LOW |

## 表格

| 编号 | 规则 | 严重级别 |
|------|------|---------|
| TB-01 | 使用标准 markdown 表格语法，不使用 HTML 表格 | MEDIUM |
| TB-02 | 术语/短语列统一不加标点；句子列统一加句号；混合情况统一加句号 | LOW |

## 标点符号

| 编号 | 规则 | 严重级别 |
|------|------|---------|
| PN-01 | 单位与数字之间不加空格（例外：产品名称如 Atlas 900）；中文与英文之间是否加空格不做强制，同一文档内风格保持一致 | MEDIUM |
| PN-02 | =、~、>、< 符号前后加空格 | LOW |
| PN-03 | 列表项标点使用保持一致 | MEDIUM |
| PN-04 | 中文文档使用全角标点，数字使用半角字符 | MEDIUM |
| PN-05 | 感叹号仅用于可能引发严重人身或设备安全后果的警告 | HIGH |
| PN-06 | 引用其他文档时添加书名号，建议增加跳转链接 | LOW |

## 目录结构

| 编号 | 规则 | 严重级别 |
|------|------|---------|
| DS-01 | 文档统一存放于 docs/ 目录下，按子目录分类管理 | MEDIUM |
| DS-03 | 与代码强关联的模块文档直接归档在对应代码目录下（如 README.md） | LOW |
| DS-04 | 每个接口对应一个 md 文件，目录内保持统一（对照 docs/zh/api_ref/ 既有结构） | MEDIUM |
| DS-05 | 新增文档目录须提供 README.md 索引 | HIGH |
| DS-06 | API 文档必须提供目录索引文件（如 `README.md` 或 `xx_list.md`） | HIGH |
| DS-07 | API 按框架/组件/语言分类时须通过子目录区分 | MEDIUM |

## 内容要求

| 编号 | 规则 | 严重级别 |
|------|------|---------|
| CT-01 | README 须包含：模块概述、构建或使用说明（面向仓内开发者） | HIGH |
| CT-02 | 内容与模块职责吻合，不包含无关主题 | MEDIUM |

## 贡献合规

| 编号 | 规则 | 严重级别 |
|------|------|---------|
| CP-01 | 提交内容与本仓通信库特性相关 | HIGH |
| CP-02 | 不包含敏感信息、种族歧视或性别歧视内容 | CRITICAL |
| CP-03 | 内容原创，不侵犯他人知识产权 | CRITICAL |
| CP-04 | 内容客观真实，不使用夸大宣传词汇 | HIGH |
| CP-05 | 不通过自动化工具短时间提交大量无害错误修正 | MEDIUM |

## 语言通顺、敏感词与术语

| 维度 | 规则 | 严重级别 |
|------|------|---------|
| 语言通顺性 | 语句通顺、语法正确、无错别字、无歧义表达、中英文混排规范 | HIGH |
| 敏感词检测 | 不包含政治敏感、歧视、夸大宣传等违规内容 | HIGH |
| 术语规范性 | 专业术语首次出现时有解释或全称说明，不使用未定义的缩写或术语 | HIGH |
| 硬件代号规避 | md 文档正文不使用内部硬件代号 CKE、Xn、GSA、MS（代码块内标识符除外），统一替换为 C++ API 类名：CKE→Event、Xn→Variable、GSA→Address、MS→CcuBuffer | MEDIUM |

## 检视输出约定

- MD 检视意见与代码意见同一 findings schema；dimension 字段写 文档规范[规则编号]，如 文档规范[HD-05]
- 每条意见给出可操作修复建议（不只点问题）；severity 按上表定级
